# 用 managed block 改寫 `.zshrc`，不整份覆蓋

v2 的做法是備份既有 `.zshrc` 再整份覆蓋。在樹莓派上實測的結果是：
原本 4863 bytes 的設定被換成 1641 bytes，使用者事後手動補回 PATH、pyenv、`.bash_aliases`
三段，但 `HIST_STAMPS="yyyy-mm-dd"` 就此消失。備份檔存在，卻沒有人會回去讀它。
所以 v3 改成只擁有 `.zshrc` 裡兩個以標記包起來的區段（head 與 tail），區段外的內容一律不動。

代價是複雜度：腳本必須判斷既有 `.zshrc` 有沒有自己載入 oh-my-zsh（決定用完整模式還是附加模式），
而且那兩個標記從第一台機器裝上去的那一刻起就是對外契約，之後不能隨便改名。
換來的是「重跑一次修好」變成安全動作，這對一支要分享給別人、要在 12 台以上機器重複執行的腳本
是必要條件。

## Considered Options

- **整份覆蓋 + 備份**（v2）：已證實等同資料遺失。
- **極簡 `.zshrc` + `~/.zshrc.d/` drop-in**：腳本完全擁有 `.zshrc`，客製化搬進 drop-in 目錄。
  否決原因是 p10k instant prompt 必須在 `.zshrc` 最上面、且它之前不能有任何輸出，
  drop-in 的載入順序會變成另一條要向使用者解釋的規則；而且對已經手改過 `.zshrc` 的機器
  （手寫 omz 的工作站有 5003 bytes 的手寫設定）仍然是破壞性的。
