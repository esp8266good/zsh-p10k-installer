# v2 骨架用兩段式判定，不逐行比對

v2 寫進 `.zshrc` 的那份骨架現在位於使用者區段，所以 v3 每次重跑都繞著它走，
結果是樹莓派與另一台 v2 機器上同一段設定各存在兩份。要修掉重複，
必須有辦法回答「這幾行是 v2 寫的，不是使用者寫的」。

第一版的做法是逐行比對：拿 v2 的骨架當一組「已知是 v2 寫的行」，
從使用者區段裡把文字吻合的行剔掉。實測的結果是它會弄壞機器：

| 機器 | 與 v2 骨架逐字吻合的行數 | 逐行剔除會刪掉 |
|---|---|---|
| 另一台 v2 機器 | 30 / 30 | 正確 |
| 樹莓派 | 30 / 30 | 正確 |
| 手寫 omz 的工作站 | 9 / 30 | `ZSH_THEME=`、`plugins=(`、`)`、instant prompt 整段 |
| 共用主機 | 12 / 30 | 上列再加 `fpath+=`、兩個 `fi` |

原因是 v2 的骨架本來就抄自 oh-my-zsh 官方的 `zshrc.zsh-template`，
所以 `ZSH_THEME="powerlevel10k/powerlevel10k"`、`plugins=(`、`)`、`fpath+=…`、`fi`
這些行在**任何** oh-my-zsh 使用者的 `.zshrc` 裡都逐字吻合。
「這行跟 v2 一樣」推不出「這行是 v2 寫的」。

所以改成兩段式，而且兩段都要過才動手：

1. **檔案層級分類**：v2 骨架那 30 行（不計空行）是不是全部都在，而且順序一致？
   實作是 subsequence 比對，允許使用者的行夾在中間。
   同時檢查反證：使用者區段裡只要出現 oh-my-zsh 官方 template 的說明註解
   （`# Uncomment the following line to use case-sensitive completion.` 之類），
   就判定為官方 template 衍生，不管吻合幾行都不回收。v2 把那些註解全刪光了，
   所以這兩件事互斥。
2. **只有第一段過了才逐行剔除**，而且剔除的是「貪婪比對命中的那幾個位置」，
   不是「文字吻合的所有行」。樹莓派在骨架後面自己加了
   `if [ -f ~/.bash_aliases ]; then … fi`，那個 `fi` 跟骨架裡的一字不差；
   按文字刪會留下孤兒 `if`，`zsh -n` 就炸。

門檻設在 30/30 而不是 90%，因為實測樣本裡 30 對 12 中間沒有灰色地帶，
放寬門檻換不到任何東西，只會讓共用主機那種檔案離門檻更近。

回收預設不做，要 `--clean-v2` 才做。那些行現在位於使用者區段，
而「區段外的一切都是使用者的」是這支腳本從第一天起的對外承諾
（見 [0001](0001-managed-block-instead-of-overwrite.md)）。
腳本沒辦法證明那 30 行是 v2 寫的而不是使用者從別處抄來的，另一台 v2 機器就是逐字吻合，
但沒有任何憑據說那不是手抄的。要打破承諾，得是使用者當場說要。

## Considered Options

- **逐行剔除**：已證實會弄壞手寫 omz 的工作站與共用主機。
- **抓頭尾錨點整段砍**（從 `# Keep non-interactive zsh clean…` 砍到
  `[[ -f "$HOME/.p10k.zsh" ]] && source …`）：會連樹莓派夾在骨架中間的
  使用者行一起砍掉。
- **完全不處理**：樹莓派與另一台 v2 機器上的重複永遠不會消失，
  而且會一直讓人以為是 v3 寫的。
